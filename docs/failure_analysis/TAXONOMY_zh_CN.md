# 自然语言驱动的 DataFrame 编程错误分类

本文是 [英文版 TAXONOMY.md](TAXONOMY.md) 的对应中文版。

本分类草案用于分析 DataAgentBench 和 PrepBench 在不同模型、后端和任务模式下的运行结果。NA 表示 Agent 侧的失败；NH 表示任务规格或澄清侧的问题。NH 不一定意味着人类犯错，因为澄清也可能来自模拟用户。这些类别用于研究标注，并非评估框架自动分配的标签。采用本分类不会自动修改既有运行的标签或评分。另外还有一个 PandasBench 面向 pandas 迁移的 P 系列分类独立保留。

## NA：Agent 侧错误

| 编号 | 类别 | 定义 | 示例 |
| --- | --- | --- | --- |
| NA1 | 任务理解与规划错误（Task Interpretation and Planning Errors） | 必要规则已经提供，但 Agent 误解了目标，或选择了即使正确实现也无法满足目标的分析方案。 | 任务要求计算各组对总增长的贡献，方案却计算各组自身的增长率。 |
| NA2 | 数据选择与解释错误（Data Selection and Interpretation Errors） | Agent 选错数据源、字段或记录，或在读取、解析、转换过程中误解数据含义。 | 将标识符当作度量值、选择错误的日期字段，或违反明确指定的格式解析日期。 |
| NA3 | 操作实现错误（Operation Implementation Errors） | 已理解所需的逻辑操作，但其表达式、算法或 API 使用不正确。 | 筛选条件、关联键、聚合函数、正则表达式或 API 参数实现错误。 |
| NA4 | 流程组合错误（Workflow Composition Errors） | 操作之间的顺序、中间状态或记录对应关系错误，或遗漏了必要的流程阶段。 | 先截取 top-K 分组再计算需要完整分母的占比，或清洗后继续使用旧表。 |
| NA5 | 输出格式与交付错误（Output Format and Delivery Errors） | 已有正确的计算内容，但 Agent 未满足明确的输出格式或交付要求。 | 提交了正确的结果表，但要求的列名、文件结构、排序或舍入方式不符合规定。 |
| NA6 | 求解未完成（Incomplete Problem Solving） | 必要阶段尚未完成，求解过程便已结束，且现有证据无法确定更具体的主要失败机制。 | 分析或验证尚未完成时预算耗尽，或 Agent 在完成任务前主动终止求解。 |

## NH：任务规格与澄清侧问题

| 编号 | 类别 | 定义 | 示例 |
| --- | --- | --- | --- |
| NH1 | 任务规则缺失或歧义（Missing or Ambiguous Task Rules） | 无法根据实际提供的任务、允许访问的数据和实际澄清确定必要规则；有证据支持多种影响答案的合理解释。 | 对重复记录求和或去重都有合理依据，但评测要求其中一种未说明的选择。 |
| NH2 | 输出约定缺失或歧义（Missing or Ambiguous Output Requirements） | 评测要求某种输出约定，但实际提供的任务和澄清未充分说明。 | 评测要求特定行顺序、舍入精度或空结果表示，但题面未说明。 |
| NH3 | 澄清不足、错误或矛盾（Inadequate or Inconsistent Clarification） | 实际澄清未可靠补足所询问的必要规则，或提供了错误、矛盾的信息，并与失败有关。 | 澄清文字描述一种排名规则，给出的例子却遵循另一种规则。 |

## 分类边界

### NA1、NA2、NA3 与 NA4

- **NA1 与实现错误：** 判断忠实执行 Agent 明确提出的方案能否满足任务。整体方案不成立支持 NA1；有效方案未被正确实现支持 NA3 或 NA4。轨迹缺少支持证据时，不应仅从错误代码反推其分析方案。
- **NA2 与 NA3：** 误解哪些字段或记录代表所需概念，属于 NA2；理解了应选择什么，但筛选条件实现错误，属于 NA3。读取、schema 和类型错误在改变输入值的解释时归入 NA2。仅 dtype 名称不同不构成错误。
- **NA3 与 NA4：** 判断该操作在正确输入和状态下能否得到正确结果。不能则优先归 NA3；能够，但流程提供了错误状态或错误衔接了结果，则优先归 NA4。单次关联使用错误的键属于 NA3；排序一张表后，仍按旧行位置拼接另一份结果，属于 NA4。

操作指的是**逻辑转换**，不以代码行数或 API 调用次数为单位。同一个操作在 PySpark 或 Ibis 中可能需要多个表达式，在 pandas 中可能只需一次调用。这种差异不应改变分类。保持语义的顺序调整或重构不属于流程错误。

API 误用不单独设为主要类别。实现某个操作时调用不支持的方法或使用非法参数，且最终因此失败，通常归入 NA3。未保存和使用操作返回的新表，则可能属于 NA4。认定后端缺少能力需要证据；未能发现已有 API，不等于后端缺少该能力。

### NA5 与计算错误、NH2

NA5 要求有证据证明计算内容正确。缺少答案文件、schema 不匹配，或评测记录显示未检查内容，都不足以单独确立 NA5。声称只有交付存在问题之前，需要补充比较，或提供代码与数据层面的证据。

Agent 违反明确的输出要求，支持 NA5；某项输出约定仅由评测要求，支持 NH2。在任务比较规则下，所需信息与数值均被保留时，格式或小数显示位数差异不构成失败。

仅显示 schema，既不能证明内容正确，也不能证明缺少物化。应检查代码和产物，确定计算是否实际求值。缺少物化不自动归为输出格式错误；应记录观察到的缺陷，并仅在证据支持时归因。

### NA6 与具体错误原因

结合阶段记录和终止前的轨迹确定求解是否未完成，并记录未完成的阶段和停止方式。仅凭超时，不能认定算法低效或存在无效循环。终止一次中间尝试后成功继续求解，不属于最终求解未完成。

若证据能够确定具体原因，例如 API 误用（NA3）或流程状态错误（NA4），应以该原因为主类别，另行记录未完成这一结果。只有证据支持求解未完成、但不足以确定更具体原因时，才以 NA6 为主类别。真实服务中断和基础设施故障与 Agent 失败分开记录。

### NH1、NH2 与 NH3

NH1 关注决定实际答案的规则；NH2 关注输出表示。未说明的 top-K 并列选择规则若会改变选出的记录，属于实质性选择规则，而不仅是格式问题。如果任意满足条件的并列选择均符合任务要求，则这些选择应视为等价，不算失败。

NH3 要求存在实际澄清交互，并有证据联系澄清缺陷与失败。Agent 带有诱导性或错误前提的提问也可能造成影响；不能根据 NA/NH 的划分推断某一侧承担全部责任。使用 clarified 模式，本身不能证明所有必要信息都已提供。

## 证据与过程标注

审核每个失败时，应检查实际提供的题面与澄清、最终 solution、相关执行轨迹和评测证据。比较未通过是一种结果，不是根因。汇总记录可用于清点和筛选，但应区分基于汇总的假设与核对原始材料后确认的发现。证据不足时，保留“归因未确定”。

按任务统计时，选择一个有证据支持的主类别，并保留独立的次要问题。不要将同一缺陷传播形成的下游差异计为多个独立失败。基础设施、reference、捕获器和比较器的问题，与 NA/NH 失败分开记录。

以下过程标签或测量值独立于最终失败类别记录：

- API 误用、运行时异常，以及将 pandas 特有 API 或默认行为套用到其他后端的证据。
- 错误是否修复，以及修复尝试次数。
- 能从轨迹归属到修复过程的 token 消耗；无法获得时标为未知，不用整个运行的 token 消耗替代。
- 完成状态、未完成阶段和停止方式，例如预算耗尽或 Agent 主动终止。

已修复的中间错误属于过程观察，不属于最终失败。分析修复率和后端友好度时，也应纳入成功运行。进行比较时，应保留模型、后端、模式、预算、资产版本和证据路径。

## 与最初 I／II 分类的映射

| 原类别 | 修订类别 | 迁移说明 |
| --- | --- | --- |
| I1 任务理解与分析方案错误 | NA1 | 基本不变。 |
| I2 数据选择与解释错误 | NA2 | 基本不变；明确包含解析和类型处理造成的输入解释错误。 |
| I3 数据处理与算法实现错误 | NA3 或 NA4 | 需审核缺陷位于单个逻辑操作内部，还是流程组合中。 |
| I4 API、执行与修复失败 | 通常为 NA3；其他情况依证据判断 | 检查具体原因，单独记录异常及修复结果；不能将所有执行失败机械映射为 NA3。 |
| I5 指令落实与结果交付错误 | NA5 | 验证计算内容正确，且输出要求明确。 |
| I6 求解流程失效 | NA6，或有证据支持的更具体原因 | 保留停止证据；超时不能证明循环或低效。 |
| II1 任务口径与必要信息缺失或歧义 | NH1 | 基本不变。 |
| II3 输出约定缺失 | NH2 | 重新编号；区分输出表示要求与实质性规则。 |
| II4 澄清信息不充分、错误或矛盾 | NH3 | 基本不变。 |

应在修订标注旁保留原始标签与理由。特别是 I3 和 I4，不能仅通过替换编号完成迁移。本文定义修订后的分类体系，不表示历史分类已经按照该体系重新审核。
